# 书籍全量学习档案

当 `sourceType=book`，或输入是一整本书、长篇 EPUB、MOBI/AZW、完整书籍 PDF/DOCX 时，必须读取本文件。目标是构建**全书覆盖、可逐项追溯、没有任意数量上限**的深度学习档案：不因“页面够长”“已达到若干条”而停止提炼，也不靠重复改写、常识扩写或堆砌同义词制造篇幅。

## 一、定位正文与章节结构

1. 读取目录、前 8000 字、`metadata.json`、`source_map.json`，建立章节账本。
2. 优先以正文标题划分章节；目录与正文标题重复时，选择正文中靠后的同名标题作为正文起点。
3. 为每个章节账本记录：章节编号、章节原名、正文起止位置、原书页码范围、PDF 页码范围/其他实际定位、提取质量说明。EPUB 必须以 OPF spine 的 `itemref` 顺序为阅读顺序，使用 `source_map.json` 中的 `epub_section` 定位，禁止用 manifest 或文件名字母顺序替代。
4. 正文超过 50K token 时逐章或逐论证单元切片；先完成一章的事实层与出处，再进入下一章。禁止把全书一次性粗读后只输出前半段。
5. 标题识别不足时，根据标题路径、原书页眉、页码和全文检索人工确认边界；不得虚构章节结构。
6. 前言、序言、引言、结语、后记、附录若含作者的方法、定义、关键限制或行动内容，作为独立单元纳入，不得仅因不是“正文第 N 章”而省略。

## 二、全量覆盖原则（无数量上限）

**核心框架、术语大全、行动规则、学习自检考点均不得设数量上限、目标条数、截断上限或“达到下限即可停止”的做法。**

### 1. 核心框架（`frameworks`）

- 收录全书所有能改变判断、行动、分析路径或项目推进方式的作者命名框架、公式、阶段、分类、矩阵、地图、检查表、流程与判断准则。
- 对作者未命名、但贯穿多个章节并构成核心论证骨架的结构，使用忠实的描述性名称收录，并明确这是页面归纳而非作者原名。
- 同一框架在不同章节出现新要素、新适用条件、新边界或新动作时，保留为同一框架的扩展来源；不得因为已有一条而丢掉后续关键内容。
- 只合并语义完全等价的重复表述；不要因“太多”删掉独立可用的框架。
- 按框架在全书中第一次被实质介绍的章节与位置排列；后续扩展只追加出处，不改变首次出现顺序。写入对应 `firstUnitId` 和连续 `sourceOrder`。

### 2. 术语大全（`glossary`）

- 穷尽收录材料中的作者命名术语、专业术语、角色称谓、流程节点、指标、英文缩写、模型要素、关键动作、易混淆概念和在理解后续章节时必须回看的概念。
- 每个术语必须说明：是什么、在书中怎样使用、与哪些概念相关、覆盖哪些单元、出处在哪里。
- 英文缩写必须写英文全称和中文含义。
- 同一术语只在语义完全相同时去重；跨章含义、条件或用法不同，保留合并后的多章节出处与差异说明。
- 不得以“术语数量已经很多”为理由停止收录。
- 按术语在全书中第一次出现并承担实际含义的位置排列；分类只作为标签，不参与排序。写入对应 `firstUnitId` 和连续 `sourceOrder`。

### 3. 行动规则（`decisionRules`）

- 穷尽提炼全书中明确的条件—行动—原因关系，包括作者直接给出的做法、判断准则、风险信号、反模式对应动作、阶段转换动作和案例中被作者明确认可的操作。
- 统一改写为“当 X，做 Y，因为 Z”，但不得把材料外经验伪装成作者规则。
- 同一规则在不同场景有不同触发条件、例外、优先级或行动路径时，拆分为独立规则，不以条数控制为由合并丢失边界。

### 4. 学习自检（`assessment.focusAreas`）

- 覆盖全书每一个具有独立判断价值的框架、概念区分、流程阶段、案例教训与行动规则；不设置题数上限。
- 每个考点记录稳定 ID、考点名称、所属章节/单元、能力层级和真实出处；不在静态页面预写题干、提示或答案。
- 在全书内同时覆盖“记忆—解释—应用—迁移”；复杂框架可以拆成多个独立考点，不因考点已多而删掉关键判断。
- 动态题目、逐题判分、难度调整和错题整理由用户复制口令后在 AI 对话中完成。
- 书中若存在章末练习、测试题或答案区，按 `question-bank-routing.md` 全量写入内部 `question-bank.json`；页面不显示识别结果或题库模式。

### 5. 详细不等于注水

- 以材料中的独立信息单元、判断价值和行动差异决定条目数量，而不是以预设条数决定内容深度。
- 不重复收录仅措辞不同、判断与行动完全相同的内容。
- 不用通用常识、模型补充、未出现的案例来填充数量；材料不足时如实标注边界。

## 三、章节知识库写作要求

每个书籍单元对应一章或有独立论证目标的章节组，保留作者推进顺序。每个 `units/uNN-<slug>.md` 必须尽可能完整记录该单元中实际出现的：

- Core Idea：章节主张及其与全书的关系；
- Frameworks Introduced：本章引入或实质扩展的全部框架、要素、适用条件和用法；
- Key Concepts：理解本章所必需的全部关键概念与区别；
- Mental Models：材料中的结构关系与因果关系；
- Anti-patterns：错误做法、出现条件、危害和材料给出的纠偏；
- Worked Examples：材料已有案例的背景、行动、结果和作者解释；
- Key Takeaways：能改变后续判断或行动的全部要点；
- Expandable Conclusions：按材料实际论证块展开，不设组数或分点上限；每组包含总结、全部必要分点、独立出处；
- Connects To：与前后章节的因果、依赖、对比、应用连接；
- Source Range：章节标题、原书页码、PDF 页码/其他实际定位。

不得用单章固定 token 预算、固定条目数或“简短易读”的名义截断作者关键论证。短章、重复章节、附录或材料不足时可自然较短，但必须如实说明边界。

## 四、全书 overview 覆盖门禁

overview 输出必须满足：

- 覆盖全书所有具有独立论证价值的章节、序言/附录关键内容，保留作者原有顺序；不得只处理前几章、摘要页、热门章节或便于概括的部分。
- `frameworks`、`glossary`、`decisionRules`、`assessment.focusAreas` 以**全书可提炼的独立内容为上限**，不设置预设最大条数，也不将最低数量当作完成标准。
- 每章/单元的 `conclusions` 以本章真实论证块为准，不设置预设最大条数；每个分组完整展开作者明确命名的框架、阶段、分类、维度、检查表与判断准则。
- 每条关键断言、框架、术语、行动规则和自检考点均有真实出处，且书籍出处必须同时显示**具体章节**与**页码定位**。
- 同时生成 `coverage-audit.md` 与 `coverage-audit.json`：前者逐章列出正文范围、已提炼内容与缺口；后者按机器契约记录每个源文件、状态、单元和页码范围。记录数量仅用于审计，不构成目标、上限或配额。
- 同时按 `summary-coverage-schema.md` 生成 `summary-ledger.json`，逐条映射全书关键主张与页面内容总结；正向或反向存在缺口时不得生成最终页面。

## 五、书籍出处格式（强制）

书籍中的每一条 `source` 必须写出具体章节和页码，优先使用以下格式：

- 有原书页与 PDF 页映射：`第3章《采购流程和销售流程》 · 原书第041–046页 · PDF第049–054页`
- 只有 PDF 页可确认：`第3章《采购流程和销售流程》 · PDF第049–054页`
- EPUB：`第3章《采购流程和销售流程》 · EPUB第3节`，如可映射页码则一并写出。
- DOCX/其他可定位书籍：`第3章《采购流程和销售流程》 · 标题路径：…… · 第N段`。
- 前言、序言、结语、后记、附录：`前言《……》 · 原书第…页 · PDF第…页`、`附录《……》 · ……`。
- 多处依据：在同一 `source` 字段中逐项列出，例如：`第2章《……》 · 原书第…页 · PDF第…页；第5章《……》 · 原书第…页 · PDF第…页`。

只在无法得到精确映射时使用“约”；不得只写“PDF第 N 页”、只写“第 N 章”、只写模糊章节范围，或省略章节名称。

## 六、生成前完整性审计

在生成 `page.json` 前逐项核对：

- 是否逐章处理到最后一章、结语与附录，而不是只处理容易概括的部分？
- 是否收录了全部作者命名框架，以及每个框架在后续章节新增的要素、条件和边界？
- 是否从各章知识库、术语、案例、反模式中穷尽汇总框架、术语、行动规则与自检考点，并仅合并真实重复项？
- 是否每条来源都有具体章节名称与页码/实际定位？
- 是否 `coverage-audit.md` 中每章都标记为已覆盖，或对缺口给出事实性原因？
- 是否把材料原意、页面改写、模型推导严格区分？
- 是否所有行动规则均能回溯到材料，而不是泛泛感想？

不通过任一项时，回到知识库补全再生成 JSON；生成 HTML 前必须通过 `verify_coverage.py`，不得手改 HTML 掩盖缺漏。
