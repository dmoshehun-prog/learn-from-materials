# 学习深度模式

学习深度必须在模型处理材料前确认。职业和兴趣不在此阶段询问；它们仍由生成后的 HTML 在首次打开时收集，并只用于用户表示没懂后的第二层画像类比。

## 选择规则

- 用户已经明确说“快速了解、抓重点、先看核心”时，使用 `quick`。
- 用户已经明确说“系统学习、深入、全面、完整覆盖”时，使用 `systematic`。
- 用户没有说明时，在开始提取和分析前只询问一次：`快速了解` 或 `系统学习`。默认选项为系统学习，但不得替用户静默选择。
- 不询问职业、兴趣、姓名、公司或联系方式。

## 快速了解（`quick`）

目标是让用户用较低时间和 token 成本掌握材料的主线，不声称穷尽全部知识。

- 顺序扫描全部文件与全部页面/幻灯片的结构，确认材料边界和主要主题。
- 只提炼决定材料主线的核心框架、重点知识、关键术语、主要结论、代表性案例与高价值行动规则。
- 所有呈现内容仍必须有真实出处；不得因快速模式放宽来源真实性、安全边界或材料/模型分层。
- 执行 `quick-workflow.md`：用章节级结构记录与展示出处核查替代全量逐块主张映射，不生成 `coverage-audit.json`、`summary-ledger.json` 或反向覆盖报告。
- 页面显著显示“快速了解模式”，说明它是重点摘要而非全量覆盖，并提供“复制系统学习版口令”。
- 不预建完整题库；测验启动后再按所选范围检查原题。未索引不等于没有题库。

## 系统学习（`systematic`）

这是原有的完整模式。

- 顺序处理全部材料范围，执行材料类型对应的高密度质量档案。
- 框架、术语、规则、结论、案例和自检考点不设数量上限，以材料中实际独立信息为边界。
- 执行结构覆盖、知识覆盖、总结双向映射、反向抽查和视觉/OCR边界检查。
- `coverage-audit.json.learningDepth` 写为 `systematic`，不得出现 `quick-omitted`。
- 页面显示“系统学习模式”。

## 页面身份

`meta.pageId` 是材料学习项目的稳定身份；初次生成后不得因内容更新、学习深度切换或 HTML 重新渲染而改变。笔记、错题、主题和读者画像都以它作为本地存储作用域。快速版升级为系统版时沿用同一 `pageId`。
