# 非书籍材料全量学习档案

当 `sourceType` 为 `slides`、`document`、`web`、`text` 或 `mixed` 时，必须读取本文件。目标是让 PPT/PPTX、PDF/Word、网页、Markdown/文本和多材料集合与书籍模式采用同一条基本标准：**按材料全部可提炼的独立信息完整覆盖、逐项可追溯、没有任意数量上限**。

不得因为材料不是书籍，就只做提纲式摘要、只抽热门页面、只列少量术语，或在框架、术语、规则、自检考点达到某个数量后停止。

## 一、共同全量覆盖原则

以下模块均不设置数量上限、目标条数、截断上限、单元限额或“达到下限即可结束”的完成线：

- `frameworks`：材料中所有能改变判断、行动、分析路径、解释结构或决策结果的命名/描述性框架、流程、阶段、分类、公式、维度、矩阵、图表结论、检查表和判断准则；
- `glossary`：所有理解材料所必需的专业术语、英文缩写、角色、流程、指标、方法、图表变量、易混概念和跨文件共用词；
- `decisionRules`：所有能忠实写成“当 X，做 Y，因为 Z”的条件—行动—原因关系，包括风险信号、阶段转换、反模式的纠偏与材料中明确认可的操作；
- `assessment.focusAreas`：覆盖所有独立框架、概念区分、数据/图表解读、关键判断、案例教训与行动规则，并为每个考点标记记忆、解释、应用、迁移能力层级；不预生成固定题目；
- `question-bank.json`：静默识别样题、真题、模拟题、章节练习和答案解析，按 `question-bank-routing.md` 保留完整原题与出处；未检测到时生成有效空索引，不在 HTML 展示识别状态；
- `contentUnits[].conclusions`：按材料真实论证块完整展开，不限制结论组和分点数量；
- `units/*.md`：不限制关键概念、案例、反模式、要点等数量；以材料事实为边界。

`frameworks` 与 `glossary` 均按材料首次实质介绍的位置排列，写入 `firstUnitId` 与连续 `sourceOrder`；分类只作为标签，不参与默认排序。多材料先按输入文件顺序，再按各文件内部位置确定首次出现。

只合并语义、判断、条件和行动均完全相同的重复内容。不要以“条目已经很多”为由删除独立内容；不要用同义反复、材料外常识或虚构例子注水。

## 二、材料结构账本

提取之后，先为每份材料建立结构账本，再开始知识库写作。账本记录的数量只用于审计，不构成输出配额。

### 1. PPT / PPTX / PPTM (`slides`)

- 按连续主题和论证推进合并为单元；不能只按每页机械拆分，也不能跳过“文字少但承载结论/图表/转场作用”的页面。
- 对每页记录：幻灯片序号、标题/主题、文字要点、图表/图片/流程图是否影响结论、与前后页关系、已提炼框架/术语/规则/自检考点。
- 若 `visual_review_recommended=true`，逐页或按关键页复核影响结论的图表、结构图、数据标注和图片文字；无法视觉核验时，把限制记录入 `coverage-audit.md`，不得将图中细节写为材料事实。
- 对空白页、封面、目录、分隔页说明其结构作用；若无学习内容可标记“无可提炼事实”，但不得静默漏过。

### 2. PDF / Word / DOCX / RTF (`document`)

- 按标题层级、正文论证、表格、图表、公式、代码块、案例框和附录建立单元；不要只抽标题和段首句。
- 对每个结构块记录：标题路径、页码/段落/表格/图号、论证功能、已提炼信息及未解析内容。
- DOCX 结构化提取必须保留正文中的表格行、脚注编号与脚注正文；图片至少保留替代文字或媒体文件名占位。`visual_review_recommended=true` 时逐项核验影响结论的图片，不能把占位符当成图中事实。
- PDF 既有文字层又有图表时，文字提取与视觉信息分别核验；表格、公式或图表若影响结论，必须在来源定位中标明表/图/段落。
- 扫描件 OCR 不确定处要保留“提取不清”标记，不能擅自补全。

### 3. 网页 / HTML (`web`)

- 按页面标题、H1–H6 标题层级、折叠内容、图表、表格、引用、脚注和更新时间建立结构账本。
- 处理长页面时分段读取到页面末尾；不得只根据页面首屏、摘要或搜索摘要完成学习页。
- 对动态加载、登录限制、折叠未展开、图片文字不可得的内容，在 `coverage-audit.md` 如实标记为未核验；不得伪造页面内容。
- 来源必须包含页面标题 + 小节标题；可得时加段落序号、表格/图号或锚点。

### 4. Markdown / TXT / RST / 纯文本 (`text`)

- 按 Markdown 标题、分隔符、编号结构、代码块、表格、引用块、段落主题和逻辑转折建立单元。
- 无标题文本按论证目标/主题连续性分块，并在账本中记录起止行或字符范围。
- 对代码、命令、配置示例，只解释材料实际表达的作用、前提与边界；不把示例扩展为未出现的实践结论。

### 5. 多材料集合 (`mixed`)

- 先建立**文件账本**：每份文件名称、类型、范围、版本/日期、提取质量、覆盖状态，以及**实际已读的页/段区间**。只运行关键词搜索、只读开头、只读目录/考纲或只读笔记，均不得标成“已覆盖”。
- 再建立**主题账本**：哪些材料讨论同一主题、互相支持/冲突/补充的关系、每个结论的来源集合。
- `contentUnits` 按跨文件知识主题而不是文件数量机械划分，但每个材料文件至少在 coverage audit 中有明确覆盖结论（有内容、无内容、无法读取或重复的事实性说明）。
- **来源层级**：课程、正文文档、原始数据是事实内容的主来源；考纲/知识点列表只标记优先级；笔记用于交叉核对和补充解释；样题/真题用于提炼命题方式、易混边界和自检考点。不得因考纲或笔记更短、更结构化，就让它们替代课程/正文成为框架、内容导学和术语的主要来源。
- 每个最终内容单元必须至少有一份课程/正文材料出处；每个框架、术语、规则、自检考点都记录来源类型（课程/笔记/考纲/样题/真题）及精确定位。样题、真题与答案解析还必须进入 `question-bank.json`；只有课程确实没有覆盖时，才可单独使用题库或笔记，并在 coverage audit 解释原因。
- 保留差异：不同文件观点、版本、数据或定义不一致时并列呈现，不擅自合并成单一立场。

## 三、非书籍出处格式（强制）

所有可见内容块的 `source` 都必须足够让读者回到原材料。多个依据用分号逐项列出。

- **PPT/PPTX/PPTM**：`文件名 · 第N页幻灯片《页面标题》`；范围：`文件名 · 第N–M页幻灯片《主题/页面标题》`。
- **PDF/Word/RTF 文档**：`文件名 · 标题路径：一级标题 > 二级标题 · PDF第N–M页`；无标题时：`文件名 · 第N段/表N/图N · PDF第N页`。
- **网页**：`页面标题 · 小节《……》 · 段落N`；有锚点或发布时间时可追加。
- **Markdown/文本**：`文件名 · 标题《……》 · 第N–M行`；无标题时：`文件名 · 第N–M行`。
- **多材料**：`文件A · …；文件B · …`。不得用“多份材料”“综合资料”替代逐文件定位。

只在定位信息确实不可得时写“约”或“未能定位”；不要省略文件名与内部定位。

## 四、生成双重覆盖审计（所有材料类型强制）

无论材料类型如何，生成学习页前必须在 `<主题>.learnkb/coverage-audit.md` 记录以下内容，并按 `coverage-audit-schema.md` 同步生成 `coverage-audit.json`：

1. **范围清单**：全部文件、页/幻灯片/标题/小节/行段范围，以及提取质量；
2. **结构覆盖**：每个范围是否已读、已进入哪个学习单元、是否因无事实内容/重复/不可解析而未形成条目；
3. **知识覆盖**：各范围贡献的框架、术语、规则、自检考点、案例、图表/表格结论与出处；
4. **视觉与 OCR 边界**：哪些图表、图片文字、公式、扫描页已核验，哪些未核验以及原因；
5. **跨材料关系**（适用于 mixed）：支持、补充、冲突、版本差异、重复关系；
6. **最终核对**：确认没有因条目数量、篇幅、材料位置或易读性而提前停止。

`coverage-audit.md` 不是对用户隐藏的内部草稿；它用于人工追溯。`coverage-audit.json` 用于与 manifest、source map 和 page JSON 交叉验证；两者缺一不可。

同时按 `summary-coverage-schema.md` 生成内部 `summary-ledger.json`：先逐范围提取关键主张，再映射到 `contentUnits` 总结，最后反向检查所有总结项是否有主张支撑。任一方向存在缺口时不得渲染。

## 五、生成前完整性审计

在生成 `page.json` 前逐项核对：

- 是否已经处理到每份材料的最后一页、最后一张幻灯片、最后一个小节/段落，而不是只处理开头或摘要？
- 是否对所有关键图表、表格、公式、代码、案例和脚注进行了与结论相匹配的核验，或如实记录限制？
- 是否穷尽汇总所有独立框架、术语、规则与自检点，并只合并真实重复项？
- 是否每条来源都保留文件名 + 内部定位，且多材料没有丢失文件边界？
- 是否 coverage audit 已记录全部范围的覆盖/缺口及事实性原因？
- 是否将材料事实、页面改写、模型补充、外部核验严格分开？

不通过任一项时，回到结构账本与知识库补全；生成 HTML 前必须通过 `verify_coverage.py`，不得手改 HTML 掩盖缺漏。
